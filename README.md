# Evaluating Low-Cost Mobile Laser Scanning for Individual-Tree Forest Inventory: Effects of Scanner, Processing Workflow and Forest Conditions

This repository contains the reproducible analysis for my MSc Environmental Modelling dissertation at UCL.

The study compares individual-tree forest measurements derived from three mobile laser scanning systems across Easy, Intermediate and Challenging forest terrain:

- **Single-sensor prototype** using one Livox MID-360 sensor
- **Dual-sensor prototype** using two orthogonally mounted Livox MID-360 sensors
- **Emesent Hovermap ST-X**

Two processing workflows are compared: **3DFin** and **RayCloudTools (RCT)**.

The analysis focuses on **diameter at breast height (DBH)** and **total tree height (TH)**, alongside individual-tree detection and the effect of manual quality control.

## 00 - Ground-truth coordinate alignment

`notebooks/00_gt_coordinate_alignment.ipynb`

This notebook transforms the field-measured ground-truth X/Y coordinates into the scanner coordinate system.

The three scanner datasets were already closely aligned with one another, so the **Single-sensor** dataset is used as the reference. For each terrain, two manually identified GT–scanner tree pairs define the rotation and translation required to align the centred coordinates. Both GT axes are also reflected where required. No scaling is applied.

### Alignment anchors

### Trees used for coordinate alignment

For each terrain, two trees were manually matched between the ground-truth dataset and the Single-sensor dataset. These matched pairs were used to calculate the rotation and position of the transformed GT coordinates.

- **Easy:** GT 20 matched Single-sensor T8, and GT 21 matched T9. Both GT axes were flipped before alignment.
- **Intermediate:** GT 1 matched Single-sensor T9, and GT 2 matched T3. No axis reflection was required.
- **Challenging:** GT 29 matched Single-sensor T23, and GT 30 matched T24. Both GT axes were flipped before alignment.

The resulting rotations were approximately **+19.27°** for Easy, **−17.60°** for Intermediate and **+30.85°** for Challenging.

The notebook checks that pairwise distances between GT trees are preserved after transformation, confirming that no scaling or geometric distortion has been introduced. It also saves the transformed coordinates, alignment parameters and before-and-after alignment figures.



## 01 - RCT data preparation

`notebooks/01_rct_data_preparation.ipynb`

This notebook reconstructs the final RayCloudTools tree-level datasets from the original RCT outputs and manual QC decisions.

The workflow:

- standardises terrain and scanner names
- reconstructs pre- and post-QC tree attributes
- incorporates manually reviewed GT–segment matches
- incorporates candidate-level QC classifications
- creates the validated measurement datasets
- calculates tree-detection metrics
- saves the processed RCT outputs

`segment_id` is used as the RCT segment identifier throughout the final workflow. An earlier derived variable, `RCT_tree_id`, used an offset from `segment_id` and is not used in the final analysis.



## 02 - 3DFin data preparation

`notebooks/02_3dfin_data_preparation.ipynb`

This notebook reconstructs the 3DFin measurement and detection datasets for all three terrains and scanners.

The workflow:

- loads the original 3DFin outputs
- standardises tree identifiers and measurement fields
- incorporates manually reviewed GT matches
- reconstructs candidate-level detection classifications
- creates the final DBH and TH measurement samples
- calculates tree-detection metrics
- saves the processed 3DFin outputs

Manual tree-height QC is used to remove incorrect TH attribution from the final TH sample. DBH measurements are not filtered using this TH-specific QC step.

A 3DFin DBH value of zero is treated as a **failed DBH extraction**, rather than evidence that the tree itself was not detected.



## 03 - Measurement analysis

`notebooks/03_measurement_analysis.ipynb`

This notebook performs the main descriptive and comparative measurement analyses for DBH and TH.

### Error definitions

Signed error is calculated as:

**error = estimate − reference**

Positive values therefore indicate overestimation and negative values indicate underestimation.

Absolute error is the absolute value of the signed error.

The main summary metrics are:

- **RMSE**
- **MAE**
- **Bias**
- **R²**

Prediction-style R² is calculated as **1 − SSE/SST**, so negative values are possible when predictions perform worse than using the mean reference value.

### Final common-tree sample

Direct comparisons between 3DFin and RCT use a strict common-tree sample.

A tree is retained only when all six required observations are available for the relevant attribute:

**3 scanners × 2 processing workflows**

The final common-tree sample contains:

| Attribute | Easy | Intermediate | Challenging | Total |
| --- | ---: | ---: | ---: | ---: |
| DBH | 9 | 21 | 18 | 48 |
| TH | 4 | 12 | 13 | 29 |

### RCT segmentation-QC analysis

The effect of RCT segmentation QC is assessed using paired pre- and post-QC measurements.

For each matched tree:

**Δ|error| = post-QC absolute error − pre-QC absolute error**

Negative values therefore indicate lower error after QC.
Bootstrap confidence intervals are generated by resampling trees with replacement within each terrain × scanner × attribute group.

### Direct workflow comparison

3DFin and RCT are compared directly on the strict common-tree sample using paired differences in RMSE:

**ΔRMSE = RMSE_RCT − RMSE_3DFin**

Positive values indicate lower RMSE for 3DFin, while negative values indicate lower RMSE for RCT.

A sensitivity analysis also checks whether the workflow comparison for Challenging-terrain Dual-sensor TH is affected by GT2, the extreme observation identified during the mixed-model diagnostics (found in the next notebook). Because this comparison is paired, GT2 is removed from both workflow vectors for this check.



## 04 - Mixed-effects analysis

`notebooks/04_mixed_effects_analysis.ipynb`

This notebook performs the inferential analysis using the strict post-QC common-tree sample.

Separate linear mixed-effects models are fitted for TH and DBH. The model structure is:

**√|error| = β₀ + Scanner + Workflow + Scanner × Workflow + Terrain + u(tree) + ε**

where `u(tree)` is a random intercept for each terrain-specific reference tree. This accounts for the six repeated scanner × workflow observations contributed by each retained tree.

The final model datasets contain:

- **TH:** 174 observations from 29 trees
- **DBH:** 288 observations from 48 trees

Models are fitted using `statsmodels` MixedLM with restricted maximum likelihood (REML). The TH model is fitted using L-BFGS, while the DBH model uses Powell after L-BFGS produced convergence and singular-covariance problems.

### Overall effects

Scanner, Workflow and Terrain are assessed using marginal Wald tests.

Because Scanner and Workflow are included in an interaction, their treatment-coded model coefficients describe effects at the reference level of the other factor. The marginal tests instead average across the remaining experimental conditions before testing overall differences.

The Scanner × Workflow interaction is tested jointly.

For DBH, significant overall effects are followed by marginal contrasts with 95% confidence intervals. Holm correction is applied across the three terrain pairwise comparisons.

### Model diagnostics and sensitivity analysis

Conditional residual diagnostics are examined for both models.

For TH, one extreme observation is identified for:

**Challenging × Dual sensor × RCT × GT2**

The TH model is therefore repeated after excluding this single observation. The other five TH observations belonging to GT2 remain in the model.

This sensitivity analysis does not change the overall TH inference.

### Scanner robustness

Scanner effects are also checked using paired Friedman tests within each:

**Workflow × Terrain × Attribute**

This gives **12 tests** in total.

Holm correction is applied across all 12 p-values, and Kendall's W is reported as an effect-size measure.


## Tree detection metrics

Tree detection is evaluated using **completeness** and **correctness**.

### Completeness

Completeness is the proportion of reference trees recovered as distinct individual detections.

If one detected candidate contains multiple reference trees, those trees are not counted as individually recovered.

### Strict correctness

Strict correctness is the number of valid reference-matched individual detections divided by the total number of detected candidates.

### Adjusted correctness

Adjusted correctness removes genuine trees that were visually confirmed in the point cloud but were absent from the field reference dataset from the denominator.

Invalid fragments, non-tree segments and under-segmented candidates remain penalised.

This separates genuine additional trees from false detections while retaining a stricter measure for comparison.


## Manual quality control

Manual QC was carried out through visual inspection of the point clouds, primarily using CloudCompare.

It was used to:

- verify GT-to-scanner tree correspondence
- identify incorrect tree-height attribution
- assess individual-tree ownership
- identify fragments and non-tree segments
- identify under-segmentation
- distinguish genuine unrecorded trees from false detections
- correct RCT segmentation geometry where required
- select coordinate-alignment anchors

RCT segmentation corrections were based on point-cloud geometry and tree ownership rather than on minimising DBH or TH error against the reference measurements.

The resulting manual decisions are stored explicitly in `data/manual_qc/` so that they remain visible as part of the analysis workflow.


## Key findings

- Tree detection was complete or near-complete in the Easy and Intermediate terrains, while individual-tree detection was more difficult in the Challenging terrain because of closely spaced and interlocking trees and under-segmentation.

- For DBH, 3DFin generally produced lower measurement error than RCT. All point estimates numerically favoured 3DFin across the nine scanner × terrain combinations in the strict common-tree comparison, although some differences were small or uncertain.

- RCT DBH estimates showed a stronger tendency towards underestimation than 3DFin.

- TH performance was more variable, with no consistent workflow advantage across scanners and terrains.

- Manual QC reduced several large tree-height errors caused by incorrect attribution or segmentation, although its effect varied between datasets and attributes.

- The mixed-effects models found no overall Scanner effect for either TH or DBH.

- For DBH, Workflow and Terrain had significant effects, with RCT showing greater absolute error than 3DFin.

- No significant Scanner × Workflow interaction was detected.

- The Friedman tests found no scanner comparison that remained significant after Holm correction.
